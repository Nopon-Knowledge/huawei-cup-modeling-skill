# 论文整合与提交审计

先以当届官方模板和开赛公告为准。本指南描述稳定的证据链和审计方法；封面、匿名范围、页数、命名与附件上限属于年度可变规则。

## 证据优先的写作顺序

1. 冻结关键结果、指标定义和单位，建立结果账本。
2. 从保存的输出生成表格和图，不手工复制或修改数字；生成与排版时读取 [图表与排版指南](figures-and-tables.md)。
3. 写模型假设、推导、算法和求解过程。
4. 写结果解释、验证、敏感性、限制和对子问题的直接回答。
5. 写问题分析、引言与摘要。
6. 润色时按 [学术表达指南](academic-writing.md)减少套话、段落模板和摘要式结论，逐项核对事实没有漂移。
7. 最后完成格式、引用、匿名、AI 披露和附件审计。

## 最低内容闭环

具体标题服从官方模板，但论文应能让评审者找到以下信息：

- 每个子问题的明确回答；
- 数据来源、处理方式和单位；
- 假设成立的理由及可能失效的情景；
- 符号、变量、目标、约束和模型机制；
- 求解或训练过程、参数和复现入口；
- 基线、评价指标、验证方案和结果；
- 敏感性、误差、不确定性或稳健性分析；
- 优点、局限、适用范围和可推广性；
- 可核验的参考文献、程序来源和 AI 使用说明。

摘要至少应包含题目处理路线、主要方法、关键数值结果、结论和真正成立的创新点。不要只列算法名，也不要在摘要中写正文没有支持的结论。

结论直接回答子问题，综合已验证贡献、适用边界与具体限制；必要的关键结果可以复述，但不逐句改写摘要。不为增加“个人思考”而编造局限、失败经历或未来实验。

## 结果账本

对论文中的关键结论维护如下字段：

| 字段 | 含义 |
|---|---|
| claim_id | 稳定编号，例如 Q2-R3 |
| 结论 | 论文准备表达的句子 |
| 指标与单位 | 数值含义和方向 |
| 来源 | 脚本、数据、输出文件与运行标识 |
| 验证 | 基线、复现者或稳健性检查 |
| 状态 | 待运行、已生成、已复核、已写入 |

只有“已复核”的定量结论进入摘要。数值四舍五入应统一，正文、摘要、表格和图中的同一指标必须一致。

## 引用与来源

- 只引用实际阅读并能定位的文献或可靠网页；核对作者、题名、年份、出版物、DOI/URL 和访问日期。
- 明确区分借鉴的方法、复用的程序、外部数据和队伍自己的改动。
- 找不到可靠来源的公式或模型，不要因为 AI 给出了名称就引用或使用。
- 引用程序、库、预训练模型和外部数据时，记录版本及许可或使用限制。
- 论文正文中的引用编号与参考文献表逐项双向核对。

## AI 使用记录

2026 任务按 [current-rules.md](current-rules.md) 所指向的官方规定执行；其他届次直接核对该届官方文件，找不到就标记规则缺口，不套用 2026 快照。保守日志至少记录：

- 日期时间；
- 工具名称、模型或版本、提供方；
- 使用环节与输入内容摘要；
- 哪些输出实际进入思路、代码、数据分析或文字；
- 队伍进行了哪些推导、修改、运行和验证；
- 对应代码、图表或论文位置。

AI 生成的代码仍需运行、测试和人工解释。若没有执行证据，不得写成“模型结果”。

### 披露与人工核验对照

论文体检和语言润色本身也属于实际工具使用。对照日志、代码注释、正文、图表与附件，检查记录是否覆盖真实使用环节；工具版本不明时如实记“未记录 / 待核验”，不要补猜或伪造提示历史。不能将 AI 自动复核写成队员已完成的人工审查。

逐项核对：工具与版本、用途与位置、主要提示方式、实际采用内容、队员修改和人工核验记录。对核心模型、推导、代码和结果，复核记录应能定位到推导、运行、对照实验或审阅者；最终表述与结论由队伍确认。

将当届官方要求单独登记为 `赛事与届次 / 来源与条款 / 声明位置 / 详情材料格式与文件名 / 例外条件 / 核验状态`。缺规则时列缺口，不能借用本科国赛的“参考文献前声明”或“AI工具使用详情.pdf”作为华为杯硬性要求。跨赛事规则核验见 [规则快照](current-rules.md)。

### 锁稿前集中体检

队伍可在内部锁稿前预留约半天完成“规则与披露核对 → 逐段体检 → 定向改写 → 人工复核 → 最终导出”，按剩余时间和论文规模调整；这是工作安排建议，不是赛事时限。时间不足时先处理科学性、来源、身份和披露等高优先级问题，明确剩余未检查范围，不为赶时间声称全文已通过。

只有问题处理状态与最终稿对应、关键修改完成实际人工复核后，才进入最终导出、逐页检查和哈希锁定。已经提交 MD5 的文件保持原样，体检仅形成独立意见，不再改写锁定稿。

## 逐层审计

### 科学与逻辑

- 每个假设是否在模型和结论中保持一致；
- 目标函数、约束、边界和单位是否正确；
- 是否存在数据泄漏、循环论证或用测试集调参；
- 基线是否足以说明复杂模型的增益；
- 结论强度是否超过验证范围。

### 数字与图表

- 表格数字可追溯且合计、百分比、排名方向正确；
- 图型与要说明的比较或结论匹配，图轴、单位、图例和误差含义完整；
- 图表相对正文版心居中，多子图对齐，题注遵循模板；
- 最终 PDF 中字体、线型、颜色和导出清晰度可读，无裁切或遮挡；
- 摘要、正文、图表和附件的关键数值一致；
- 随机实验说明种子或重复次数。

### 表达与论证

用户明确要求 AI 痕迹检测、综合评分或 A–E 分级时，按 [AI 痕迹评阅指南](ai-trace-review.md)补充证据表与覆盖说明；常规审稿无需强制打分。

- 过渡词表达了实际关系，段首段尾没有无信息的重复；
- 段落按论证组织，没有为凑结构而扩写或随意拆分；
- 作者判断、因果解释、显著性和局限都有相应依据；
- 数值精度与误差表达有依据，图题说明对象、条件或已验证发现；
- 结论回答子问题，润色前后的事实、引用、公式与结论强度一致。

### 格式与匿名

- 使用当届官方模板，不自行替换封面元素；
- 按当届规则检查学校、院系、姓名、学号、队号、致谢、文件属性和附件路径；
- 人工逐页检查 PDF，尤其是页眉页脚、图中水印、代码截图和文档元数据；
- 文件名、题号、队号、扩展名和附件结构符合当届公告。

### 提交与锁稿

- 在锁稿前生成最终 PDF 并检查字体、公式、图片、分页和可复制文本；
- 使用预检脚本计算 MD5 与 SHA-256，记录文件大小和修改时间；
- 由两人比对系统中的题号、队号、MD5 和本地文件；
- 提交 MD5 后不再编辑、重导出、压缩或“修复”PDF；
- 在当届规定的上传窗口提交与已登记 MD5 完全一致的 PDF，确认系统状态并保留时间与成功截图。

## 预检脚本

基础用法：

```bash
python3 /path/to/huawei-cup-modeling/scripts/preflight_submission.py PAPER.pdf \
  --manifest submission/hash-manifest.json
```

只有在当届官方公告确认后，才显式增加年度可变条件。下面的全大写值均须替换为已核验值。官方直接给出字节数时，将其作为硬阈值；若只写 MB 且未说明十进制或二进制换算，须记录队伍采用的换算约定，并把脚本结果视为保守筛查，不能据此宣称正式合规：

```bash
python3 /path/to/huawei-cup-modeling/scripts/preflight_submission.py PAPER.pdf \
  --expected-name OFFICIAL_FILENAME.pdf \
  --max-paper-bytes OFFICIAL_PAPER_BYTE_LIMIT \
  --attachment ATTACHMENT.zip \
  --max-attachment-bytes OFFICIAL_ATTACHMENT_BYTE_LIMIT \
  --identity "学校名称" \
  --identity "队员姓名" \
  --identity-start-page OFFICIAL_START_PAGE \
  --strict \
  --manifest submission/hash-manifest.json
```

锁稿后或上传前，用记录的哈希再次验证同一个字节文件：

```bash
python3 /path/to/huawei-cup-modeling/scripts/preflight_submission.py PAPER.pdf \
  --expected-md5 RECORDED_MD5 \
  --strict
```

PDF 结构检查需要 `pdfinfo`，身份扫描需要 `pdftotext`；工具缺失时会警告，`--strict` 会把未完成的检查视为失败。身份扫描起始页必须来自当届规则。文本未检出身份词不等于匿名合规：图片、水印、页眉页脚、元数据及不可提取文字仍须人工逐页检查。脚本从不覆盖已有清单或任何输入文件；如需重做清单，另取新文件名并保留旧记录。清单已默认隐藏绝对路径和身份词原文，但仍含文件名、时间、大小与哈希，比赛期间不要公开。
